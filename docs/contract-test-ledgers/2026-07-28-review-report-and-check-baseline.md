# Review report and configured-check baseline contract ledger

| Invariant | Risk It Prevents | First Test / Proof | Status |
| --- | --- | --- | --- |
| Review correlation uses stable IDs and target bindings, not exact coverage prose or array order. | A semantically valid Closure report terminates delivery because the reviewer paraphrased coverage or reordered outcomes. | `Closure hash and repair outcomes bind the exact sorted defect/finding coverage` and `needs-work defects become fixed only after implementation and enter correlated Closure` | green |
| Every review target revision owns four report-only repair attempts. | An earlier Closure consumes the only repair and makes a later valid revision unrecoverable. | `code review gets four report-only repairs per target revision` and `target fingerprint and prepared-launched-accepted review transition are exact` | green |
| A terminal malformed review resumes only when its exact current discriminator matches the enclosing Run outcome, the authorized target is unchanged, and the per-revision report budget is unexhausted. | A legacy or ambiguous terminal state gains authority, recovery reruns implementation, adopts a stale worktree, or loops after all report repairs are consumed. | `terminal report recovery requires the exact current terminal discriminator`; `legacy terminal direct review without its discriminator is unsupported before owner lock`; `an exhausted malformed Closure report remains terminal on replay` | green |
| A configured-check failure is task-owned only when it is new or changed from the clean base. | Unrelated repository failures consume implementation cycles and block a scoped task. | `an unchanged check failure already present on the base is recorded without reworking the task` | green |
| `agent:auto` is execution authorization after a trusted claim; `agent:running` is status only. | A removed status label revokes valid work and terminally safety-blocks an authorized issue. | `agent:auto remains authorization when the running status label disappears after claim` | green |
| A trusted claim comment is observed before the Runner adds `agent:running`. | A failed or forged claim comment leaves an issue looking actively owned. | `public runIssue reaches review-ready only after ordered durable checks, proof, and publication`; `a rejected claim comment never grants the running status label` | green |
| Every ordinary blocked terminal is externally visible as a settled blocked status before the durable terminal outcome is committed, without restoring revoked authorization or removing unrelated labels. | Durable state says blocked while GitHub continues to show `agent:running`; a crash after the label effect or either post-effect state write, or a legacy terminal, leaves the two sources permanently divergent. | `ordinary external safety and exhausted terminals publish the blocked issue status`; `blocked label delivery resumes from its durable intent without rerunning work`; `blocked label delivery survives a crash after the remote effect without duplicating work or labels`; `blocked terminal replay repairs a stale running label without rerunning work`; `blocked transition preserves concurrent labels and never restores revoked authorization`; `blocked transition resumes when the post-effect projection write fails` | green |
